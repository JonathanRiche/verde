# src/platform: window system layer

A Wayland client written from scratch in Zig. It does not link or dlopen libwayland-client,
libxkbcommon, libdecor or libwayland-cursor. It speaks the wire protocol over the Unix socket
itself (`WAYLAND_SOCKET`, or `$XDG_RUNTIME_DIR/$WAYLAND_DISPLAY`), passing fds with
SCM_RIGHTS. It uses only Linux syscalls; libc is not required.

`root.zig` picks the backend at comptime, all with the same `App`/`Window`/`Event` API:
Wayland on Linux/BSD (this README), AppKit on macOS (`macos/README.md`; no Objective-C sources,
the runtime is dlopened) and Win32 on Windows (`windows/README.md`). `paths.zig` (`prefPath`)
is shared and follows SDL3's per-OS rules.

## Layout

| file | role |
| --- | --- |
| `present.zig` | Contract with `src/gpu`: dmabuf images, damage, `BufferId`. |
| `wayland/wire.zig` | Connection, object table (id reuse, zombies until `delete_id`), marshalling, fd queue, buffered non-blocking I/O, `roundtrip`, `wl_display.error`, `PALETTE_WAYLAND_DEBUG` trace. |
| `../../tools/wayland-scanner.zig` | Build-time generator: protocol XML (vendored in `../protocols`) to typed bindings (`wayland_protocol` module). |
| `wayland/backend.zig` | `App` / `Window`: globals, seat, xdg-shell, scaling, frame pacing, buffers, IME, cursor, activation. |
| `wayland/input.zig` | Click counting, scroll conversion, pointer-frame accumulator. Pure; unit tested. |
| `wayland/xkb.zig` | XKB keymap text-format parser and key lookup. Pure Zig; unit tested. |
| `wayland/keysym.zig`, `keysym_data.zig` | Keysym names, keysym/Unicode tables, keysym to `event.Keycode`. Data is generated by `tools/gen-keysyms.zig` and checked in. |
| `wayland/selection.zig` | Clipboard and primary selection (shared generic implementation). |

## Using it

```zig
const platform = @import("palette").platform;

const app = try platform.App.init(gpa, .{ .app_id = "my-app", .environ = init.minimal.environ });
defer app.deinit();
const win = try app.createWindow(.{ .title = "Hello", .width = 800, .height = 600 });
defer win.destroy();

var e: palette.event.Event = undefined;
while (app.waitEvent(&e, null)) switch (e) {
    .resized => |r| { /* re-create swapchain at r.pixel_width x r.pixel_height, redraw */ },
    .frame => { /* compositor ready: render, then win.present(buf, damage) */ },
    .close_requested, .quit => break,
    else => {},
};
```

* `pollEvent` never blocks. `waitEvent(ev, timeout_ns)` blocks in `ppoll` on the socket,
  the wakeup eventfd, the key-repeat timerfd and any pending clipboard writes. An idle app
  uses 0% CPU (measured: 0 ticks over 5 s).
* `App.wakeup(u64)` is thread-safe. It posts `Event.user`; identical pending values are
  coalesced.
* Text in events (`text_input`, `text_editing`) stays valid until the next `pollEvent` or
  `waitEvent` call.
* Sizes: `logicalSize()` is in surface units. `pixelSize()` is the buffer to render, equal
  to `round(logical * scale)` when `wp_viewporter` is present (the viewport destination is
  the logical size). Without viewporter it is `logical * integer scale` and
  `wl_surface.set_buffer_scale` is used.
* Scale priority: `wp_fractional_scale_v1` (n/120), then `wl_surface.preferred_buffer_scale`,
  then the largest scale among the outputs the surface is on. `resized` fires whenever the
  logical size, pixel size or scale changes.

### Frame pacing and presentation (GPU lead)

1. Export each swapchain image once as a dma-buf and call `win.importDmabuf(image)`, which
   returns a `BufferId`. This uses `create_immed` and does one roundtrip to catch `failed`,
   so do it at swapchain creation, not per frame. The fds are `dup`'d into the socket
   queue, so the GPU side keeps ownership and may close its fds whenever it likes.
2. Per frame: pick a buffer where `win.bufferReleased(id)` is true. Render into it, call
   `win.requestFrame()`, then call `win.present(id, damage)`. `present` attaches, sends
   `damage_buffer` for each rect (an empty slice means full damage), updates the viewport
   or buffer scale, commits (including the frame callback) and does a non-blocking flush.
3. `Event.frame` arrives once per `requestFrame` when the compositor wants the next frame.
   If `requestFrame` was called without a following `present`, the surface is committed
   automatically before the next poll, so the callback still fires.
4. Render only on `frame` or after input that changed state. Compositors stop sending
   frame callbacks for hidden surfaces (and possibly while the session is locked), so never
   block waiting for one.
5. Explicit sync (`wp_linux_drm_syncobj`) is not wired up. Buffers rely on implicit dma-buf
   fences.

`app.dmabufFeedback()` returns the `(format, modifier)` pairs from the default feedback (v4
format table, read with mmap) plus the main device `dev_t`, or the v3 `modifier` events on
older compositors. `importShm(fd, w, h, stride, format)` is the CPU fallback used by the
examples.

## Protocols and versions

Required: `wl_compositor` (≤6), `wl_shm`, `xdg_wm_base` (≤6).
Optional: `wl_seat` (≤9, so key repeat stays client-side), `wl_output` (≤4),
`wl_data_device_manager` (≤3), `zwp_primary_selection_device_manager_v1`,
`zxdg_decoration_manager_v1`, `wp_viewporter`, `wp_fractional_scale_manager_v1`,
`wp_cursor_shape_manager_v1`, `zwp_text_input_manager_v3`, `zwp_linux_dmabuf_v1` (≤4),
`xdg_activation_v1`.

## Input details

* **Pointer** events are grouped per `wl_pointer.frame` and emitted in this order: enter,
  motion (with `xrel`/`yrel` and `ButtonState`), buttons, wheel, leave. A leave is reported
  immediately so that a following enter is ordered after it. Clicks count up within
  500 ms and 6 logical px for the same button. Wheel values are in lines with the SDL sign
  convention (+y means away from the user). The value comes from `value120`/120, then
  `discrete`, then pixels/10. Finger and continuous sources use pixels/10 and set
  `precise`.
* **Keyboard**: the keymap fd is mmapped (MAP_PRIVATE) and parsed by `xkb.zig`.
  `KeyEvent.key` is the level-1 keysym of the active group, so Ctrl+C reports `.c` and
  Shift+1 reports `.1`. On non-Latin layouts it falls back to a Latin group, then to the
  US position of the scancode. `codepoint` is the keysym with modifiers applied, including
  the Caps Lock transform. `text_input` is emitted for printable keys unless Ctrl, Alt or
  Super is held, or an IME preedit is active. Repeat uses `repeat_info` and a timerfd;
  modifier keys and keys with `repeat=No` do not repeat.
* **IME** (`text-input-v3`): `startTextInput(rect)`, `setTextInputRect`, `stopTextInput`.
  On `done` the events are applied in protocol order: `text_editing("")` if a preedit was
  showing, then the `text_input` commit, then the new `text_editing` preedit with its
  cursor.
* **Clipboard**: offers `text/plain;charset=utf-8`, `UTF8_STRING` and `text/plain`.
  Outgoing `send` requests become non-blocking write jobs serviced from the poll loop.
  `get*Text` reads through a pipe with a 1 s bound and returns our own text directly when
  we own the selection. `clipboard_update` is emitted on every `wl_data_device.selection`.
  The primary selection works the same way.

## Not implemented (by design or yet)

* XKB dead keys and Compose sequences: the keysym is reported, but no composed text.
  Actions in the keymap are skipped; virtual-modifier mappings come from
  `modifier_map` + interpret and explicit `vmod=` declarations.
* A cursor theme fallback when `wp_cursor_shape_v1` is missing (no Xcursor loader).
  `hidden` works everywhere.
* Drag and drop: offers are destroyed.
* Client-side decorations: `Decorations.client` only asks the compositor not to draw any.
* Per-surface dmabuf feedback, `wp_presentation` timing, explicit sync, touch and tablet
  input, the startup `XDG_ACTIVATION_TOKEN` (pass it to `Window.activate` yourself), and
  multi-seat (the first seat wins).

## Testing

```
zig build test-wayland                       # codec, scanner, keysyms, xkb, input, selection
zig build run-wayland-info                   # globals + dmabuf format/modifier pairs
zig build run-wayland-window -- --seconds 5 [--animate] [--second-window]
PALETTE_WAYLAND_DEBUG=1 zig build run-wayland-window -- --seconds 1   # protocol trace
```

Test windows must use an app_id starting with `palette-test`. The dev desktop routes them
to the headless `PALETTE-TEST` output, silently and without focus.
